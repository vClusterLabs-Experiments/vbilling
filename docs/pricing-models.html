Pricing Models

Four ways AI clouds and enterprises charge for GPUs and inference, and the vBilling setup for each. Most providers mix them: dedicated capacity for steady load, tokens for everything else.

ModelThe customer pays forMetered fromWho pays for idle GPUs
Dedicated GPUs and endpointsGPU-hours while GPUs are allocated, per second, and control plane hoursKubernetesThe customer, who can scale to zero
Serverless inferenceInput, cached input and output tokens, per modelThe AI gatewayThe provider
BlendedBoth, on one planBothEach side of the plan
Enterprise chargebackThe same quantities at internal rates, reported, not invoicedEitherEach team

None of them bills GPU utilization: a GPU allocated to one customer cannot be sold to another, used or not. Utilization is recorded next to GPU-hours for showback when the DCGM exporter is installed. See How Metering Works.

Dedicated GPUs and endpoints

A customer gets GPUs of its own: whole nodes (Private Nodes, dedicated nodes), a model endpoint with its own replicas, or, for internal teams, GPU pods on shared nodes. vBilling bills each GPU for every second it is allocated: from a container's start to its end, or every second a whole node is healthy. Scaling an endpoint to zero replicas stops the bill; a node that is down, a GPU whose driver is not ready, and a paused cluster are not billed.

tenantSource: platform # the Platform Tenant pays metering: cpuMemoryBasis: requests # exact; the default billing: defaultPlanCode: dedicated-a100 collectionDelay: 75s # on spot or preemptible GPUs adapters: [stripe] stripe: existingSecret: stripe-keys autoSubscribe: true priceCard: plans: dedicated-a100: vcluster_gpu_hours: sku: {NVIDIA-A100-SXM4-40GB: "2.20"} names: {NVIDIA-A100-SXM4-40GB: A100 40GB GPU-hour} vcluster_instance_hours: {amount: "0.10", name: Cluster control plane hour} vcluster_cpu_core_hours: {amount: "0", name: vCPU core-hour (included)} vcluster_memory_gb_hours: {amount: "0", name: Memory GiB-hour (included)} enforcement: mode: enforce inCluster: true # clusters with their own nodes
  • Whole nodes also bill vcluster_private_node_hours, per instance type. Price the node and set the GPU to 0, or the other way round, so a node is not charged twice.
  • With CPU and memory billed on requests, a pod that requests nothing is billed nothing for either; give pods default requests with vCluster's policies.limitRange.
  • An endpoint whose engine runs in the customer's own cluster can bill tokens too, with a second count from the engine: see the cross-check under Usage Sources.

Serverless inference

The provider runs shared models; customers call them through an AI gateway and pay per token. The gateway records every request, vBilling bills each request once (pushed records and the gateway's own log, read back, deduplicate), and a customer that is suspended or paused is blocked at the gateway, because it has no cluster to stop.

records: litellm: true # LiteLLM's generic API logger posts each request pullLiteLLM: url: http://litellm.litellm.svc:4000 existingSecret: litellm-admin # key: litellm-key billing: defaultPlanCode: serverless adapters: [stripe] stripe: existingSecret: stripe-keys autoSubscribe: true priceCard: plans: serverless: inference_input_tokens: {per: 1000000, sku: {qwen2.5-7b-instruct: "0.20"}} inference_cached_input_tokens: {per: 1000000, sku: {qwen2.5-7b-instruct: "0.05"}} inference_output_tokens: {per: 1000000, sku: {qwen2.5-7b-instruct: "0.60"}} enforcement: mode: enforce gateway: litellm: true # block suspended and paused customers' teams
  • Each customer is a LiteLLM team: create teams with the tenant ID as their team_id, or list the team IDs in the tenant's vbilling.vcluster.com/aliases.
  • Set general_settings: {user_api_key_cache_ttl: 5} in LiteLLM, or a block takes up to 60 seconds to apply.
  • The model group is the SKU, so each model has its own price. Cached input is its own metric; vLLM reports cached tokens with --enable-prompt-tokens-details.
  • Tier prices: requests that ask for a service_tier carry it as a dimension. Split Stripe meters by it (stripe.splitMetersBy: [sku, service_tier]) and price each tier's meter; the price card prices SKUs, so create tier prices in Stripe, tagged metadata[vbilling_plan].
  • Batch prices: vBilling has no batch flag. Serve batch traffic under its own model name, which is then its own SKU and price.
  • A shared engine serves every customer, so its own token counters cannot be split per customer and a per-tenant cross-check against them does not apply.

Blended

One customer buys dedicated capacity and tokens: put both sets of prices in one plan (a Stripe subscription holds up to 20 prices), and configure both sources. Dedicated hours cover steady demand; tokens cover what is left. On Metronome, one rate card holds both.

Enterprise chargeback

Teams of one company use the GPUs, and finance allocates the cost instead of invoicing it. Meter the same way, and send usage to finance instead of a payment platform:

adapters: [webhook] # CloudEvents batches to your data platform webhook: url: https://finance.internal.example/vbilling enforcement: mode: observe # record states, stop nothing
  • Monthly statements: GET /api/v1/usage?group_by=tenant,sku&format=csv, at your internal rates.
  • Lago, self-hosted, turns the same usage into statements per team without collecting payment.
  • vBilling has no budgets yet: alert on usage from your data platform or from Lago.

Commitments, prepaid credit and discounts

These live in the billing platform; vBilling meters, and acts on the platform's alerts.

NeedWhere
Prepaid credit that stops the customer when it runs outMetronome contracts with prepaid commits. Its balance alert becomes a billing state: enforcement.rules: "alerts.low_remaining_contract_credit_balance_reached=paused" pauses clusters and blocks gateway teams.
Committed spend, reserved capacity, volume tiersMetronome rate cards and contracts, Stripe tiered prices, Lago graduated charges.
Included allowances (for example, the first 32 GiB of storage)Metronome or Lago free units, or a Stripe tiered price with a free first tier.
Payment, tax, dunningStripe, directly or linked from Metronome. Failed payments become billing states through the webhooks.

The price card creates per-unit prices. Create tiered prices in Stripe yourself, tagged metadata[vbilling_plan], and autoSubscribe uses them like any other.
