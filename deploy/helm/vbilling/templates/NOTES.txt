Every endpoint except /healthz and /readyz needs the API token (the dashboard asks for it).
{{- if .Values.api.token }}
It is api.token.
{{- else if .Values.api.existingSecret }}
It is key api-token of Secret {{ .Values.api.existingSecret }}.
{{- else }}
The chart generated one; upgrades keep it.
{{- end }}

  export VBILLING_TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ include "vbilling.apiTokenSecret" . }} -o jsonpath='{.data.api-token}' | base64 -d)
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "vbilling.fullname" . }} {{ .Values.api.service.port }}
  curl -s -H "Authorization: Bearer $VBILLING_TOKEN" localhost:{{ .Values.api.service.port }}/api/v1/status      # destinations, lag, last window
  curl -s -H "Authorization: Bearer $VBILLING_TOKEN" "localhost:{{ .Values.api.service.port }}/api/v1/usage?group_by=tenant,sku"
  curl -s -H "Authorization: Bearer $VBILLING_TOKEN" localhost:{{ .Values.api.service.port }}/api/v1/reconcile   # ledger vs billing platform, previous UTC day
  open http://localhost:{{ .Values.api.service.port }}/                   # usage dashboard

Gateways send usage (POST /api/v1/events and /api/v1/records) with the ingest token, never the API token.
{{- if .Values.api.ingestToken }}
It is api.ingestToken.
{{- else if .Values.api.existingSecret }}
It is key ingest-token of Secret {{ .Values.api.existingSecret }}; without that key, vBilling generates one in its data volume (DATA_DIR/ingest-token).
{{- else }}
The chart generated one; upgrades keep it.
{{- end }}
{{- if not .Values.api.existingSecret }}

  kubectl -n {{ .Release.Namespace }} get secret {{ include "vbilling.fullname" . }} -o jsonpath='{.data.ingest-token}' | base64 -d
{{- end }}
{{- if .Values.api.tenantIngestTokens }}
A gateway that serves one tenant uses that tenant's token from api.tenantIngestTokens instead.
{{- end }}

Keep the dashboard and the API on an operator network, and never hand the API token to a tenant.
See https://vclusterlabs-experiments.github.io/vbilling/security.html
{{- if .Values.configCheck.enabled }}

Before every install and upgrade, a Job checks the new configuration the way vBilling
does at start-up. An upgrade that fails on it changed nothing, and vBilling keeps metering:

  kubectl -n {{ .Release.Namespace }} logs job/{{ include "vbilling.configCheckName" . }}
{{- else }}

WARNING: the configuration check is off (configCheck.enabled). vBilling is one pod: a value
it refuses at start-up stops all metering until the release is rolled back.
{{- end }}
{{- $dataClass := .Values.persistence.storageClass | default "" }}
{{- $archive := .Values.persistence.archive }}
{{- if not .Values.persistence.enabled }}

WARNING: persistence is disabled. The ledger is the durable outbox for usage that
has not reached your billing platform yet; without a volume it is lost on restart.
{{- else if not $archive.enabled }}

WARNING: there is no archive volume (persistence.archive.enabled). The data volume holds
the only copy of the usage ledger: losing that volume, or its node when the storage is
node-local, loses the ledger, and segments older than 7 days are deleted without a copy
for invoice disputes. Enable the archive on storage that does not fail together with the
data volume (another storage class or failure domain): it then also holds the ledger mirror,
a live copy from which vBilling restores itself. A bucket through a CSI driver holds the
archive, but no mirror.
{{- else if and (not $archive.existingClaim) (eq $dataClass ($archive.storageClass | default "")) }}

WARNING: the data volume and the archive volume use the same storage class ({{ $dataClass | default "the cluster's default" }}).
If that class is node-local, or all of it sits in one failure domain, one failure takes the
ledger and its archive together. Give the archive another class (persistence.archive.storageClass)
or a claim on other storage (persistence.archive.existingClaim).
{{- end }}
{{- if and .Values.persistence.enabled $archive.enabled (eq (include "vbilling.ledgerMirror" .) "off") }}

WARNING: the ledger mirror is off (persistence.archive.mirror). The archive holds segments
older than 7 days only: losing the data volume loses every newer record that has not
reached your billing platform, and vBilling cannot restore itself.
{{- end }}
